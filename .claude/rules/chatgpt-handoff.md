# ChatGPT 引き継ぎ・重複作業防止ルール

このルールは KAME LIFE GUIDE での Claude Code 作業に常時適用する。

## 1. 重複作業防止ゲート

作業開始前に、直近の作業報告・既存監査・Git履歴・現在の完了状態を確認し、対象を次の4区分に整理する。

- 完了済み
- 確定済み
- 未解決
- 今回実行

完了済み・確定済みの調査、監査、検証、修正を再実行しない。既存結果を固定入力として再利用し、未解決部分だけを処理する。

再検証を許可するのは次の場合だけ。

- 新しい矛盾が見つかった
- 新しい証拠が得られた
- 対象データ／コードが変更された
- ユーザーが明示的に再検証を指示した

## 2. 実装作業の既定終了点 — 検証後は merge まで進める

ユーザーが実装・修正を指示した作業では、特別な停止指示がない限り、**PR作成を終了点にしない**。

既定フローは次とする。

**実装 → 検証 → commit → push → PR作成 → 最終差分確認 → merge → main反映確認**

検証がすべてPASSし、Scope Lock違反・Blocker・新しい矛盾・意図しない変更がなければ、同一作業内でmergeまで進める。

次の場合だけmergeせずSTOPする。

- ユーザーが明示的に「mergeしない」「PRで止める」「承認待ち」と指示した
- Blocker、テスト失敗、競合、Scope Lock違反、新しい重大な矛盾がある
- 破壊的変更、不可逆操作、またはユーザー判断が必要な選択肢が発生した
- 権限・認証・環境制約によりmergeできない

単に「安全のため」「いつもの手順だから」という理由だけでPR作成後に停止してはならない。

merge後は main に対象commit／変更が実際に含まれることを確認してから完了扱いにする。

## 3. ChatGPT 引き継ぎ用報告 — 必須

各作業の最後に、通常の説明とは別に、必ず **「ChatGPT引き継ぎ用報告」** を出力する。

この報告は **単一のコードブロック1個だけ** にまとめる。ユーザーがスマートフォンでコードブロックのコピーボタンを1回押し、そのままChatGPTへ貼り付けられる形式にする。

ユーザーに長文の手動範囲選択を要求してはならない。

コードブロック内には最低限、次を含める。

1. 作業名／基準branch・commit
2. 完了済みとして固定した事項
3. 今回確定した事実
4. 実際に変更した内容（調査のみなら「変更なし」）
5. 検証結果と実測値
6. commit hash／push／PR番号／merge結果（該当時）
7. 未解決事項
8. Scope Lockにより触らなかった事項
9. 次工程の判断に必要な情報

報告は簡潔にするが、ChatGPTが次工程を判断するために必要な証拠・数値・ファイル名・判定理由を省略しない。

## 4. 終了条件

作業は、実装や調査が終わっただけでは完了ではない。

実装作業では原則として **検証 → PR → merge → main反映確認 → 状態整理 → ChatGPT引き継ぎ用報告** までを完了条件とする。

調査のみ、または明示的にmerge禁止の作業では、指定された停止点を優先する。
