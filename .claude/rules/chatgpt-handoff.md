# ChatGPT 引き継ぎ・重複作業防止ルール

このルールは KAME LIFE GUIDE での Claude Code 作業に常時適用する。

## 1. 重複作業防止ゲート

**作業開始前に `docs/AI-HANDOFF.md` を読む。** これが現在状態の唯一の正本であり、
下の4区分はこのファイルの節にそのまま対応する。Git履歴や過去の作業報告を漁り直す必要はない。

| 区分 | AI-HANDOFF.md の節 | 扱い |
|------|--------------------|------|
| 完了済み | `COMPLETED` | 固定入力。再調査・再監査・再実装しない |
| 確定済み | `FIXED_FACTS` | 固定入力。再検証しない |
| 未解決 | `UNRESOLVED` | 判断待ち / HOLD / 新発見。勝手に全部処理しない |
| 今回実行 | `NEXT` | **ここに書かれた1工程だけを実行する** |

完了済み・確定済みの調査、監査、検証、修正を再実行しない。既存結果を固定入力として再利用し、`NEXT` の対象だけを処理する。

再検証を許可するのは次の場合だけ。

- 新しい矛盾が見つかった
- 新しい証拠が得られた
- 対象データ／コードが変更された
- ユーザーが明示的に再検証を指示した

`AI-HANDOFF.md` が存在しない・明らかに古い場合は、作業を始める前にまず現在状態へ更新する。
ユーザーの指示が `NEXT` と食い違う場合はユーザーの指示を優先し、作業後に `NEXT` を実態へ更新する。

## 1-2. 作業終了時の AI-HANDOFF.md 更新（必須）

各作業の完了後、**同じPRの中で** `docs/AI-HANDOFF.md` を更新する。更新しないまま完了扱いにしない。

- 完了した `NEXT` → `COMPLETED` へ移す（PR番号・merge commit・**確定した結論**を必ず書く）
- 新たに確定し今後は入力として使う事実 → `FIXED_FACTS`
- 本当に未解決のものだけ → `UNRESOLVED`（判断待ち / HOLD / 新発見 を区別する）
- 次工程 → `NEXT` に**1つだけ**設定（対象 / Scope / 変更禁止 / 完了条件を書く）
- `CURRENT_BASE` の main commit と最終更新日を書き換える
- 古くなった状態記述を残さない。経緯は `AI_CHANGELOG.md`、恒久ルールは `CLAUDE.md` に置く

禁止事項

- `COMPLETED` と `NEXT` に同じ作業を同時に置かない
- `FIXED_FACTS` に書いた事項を `NEXT` で再調査させる構造にしない
- 裏付け（PR番号 / merge commit）のないものを `COMPLETED` に書かない
- `NEXT` を複数工程の詰め合わせにしない

## 2. 実装作業の既定終了点 — **PR 作成で停止する**

> **2026-09-03 Owner 裁定（D-01・案B）により変更。** 変更前は「検証後は merge まで進める」
> だったが、憲法 §2.6-I1 / §2.3-R1 / §4.3-R1「Merge は RO-1 のみが実施 MUST。
> Actor は Merge しては MUST NOT」と矛盾していた。憲法 §1.3-R1（上位優先）に従い、
> 下位規則である本節を憲法へ合わせる。

ユーザーが実装・修正を指示した作業では、**PR 作成が既定の終了点**である。

既定フローは次とする。

**実装 → 検証 → commit → push → PR作成 → 最終差分確認 → Owner へ引き渡し**

**Actor（RO-2 / RO-3）は merge しない。** 検証がすべて PASS していても merge しない。
merge・公開は RO-1（Owner）のみが実施する（憲法 §2.6-I1）。

PR を引き渡すときは、Owner が merge を判断できるだけの材料を添える。

- 検証項目と PASS / FAIL の実測値
- Scope Lock 外の変更が 0 件であることの実測
- 変更前後の行数・件数
- 破壊的変更・不可逆操作の有無
- **merge を推奨するか否かと、その理由**

次の場合は **PR も作らず STOP** し、Owner 判断へ戻す。

- Blocker、テスト失敗、競合、Scope Lock 違反、新しい重大な矛盾がある
- 破壊的変更、不可逆操作、またはユーザー判断が必要な選択肢が発生した
- 成果物が品質基準に達していない（`closeout-gate.md` の「品質不足による STOP」）

## 3. ChatGPT 引き継ぎ用報告 — 必須

各作業の最後に、通常の説明とは別に、必ず **「ChatGPT引き継ぎ用報告」** を出力する。

この報告は **単一のコードブロック1個だけ** にまとめる。ユーザーがスマートフォンでコードブロックのコピーボタンを1回押し、そのままChatGPTへ貼り付けられる形式にする。

ユーザーに長文の手動範囲選択を要求してはならない。

コードブロック内には最低限、次を含める。

1. 作業名／基準branch・commit
2. 完了済みとして固定した事項
3. 今回確定した事実
4. 実際に変更した内容（調査のみなら「変更なし」）
5. 検証結果と実測値
6. commit hash／push／PR番号／merge結果（該当時）
7. 未解決事項
8. Scope Lockにより触らなかった事項
9. 次工程の判断に必要な情報

報告は簡潔にするが、ChatGPTが次工程を判断するために必要な証拠・数値・ファイル名・判定理由を省略しない。

## 3-2. NEXT HANDOFF ブロック — 必須

完了報告の**末尾**に、必ず次のブロックを出す。`docs/AI-HANDOFF.md` の更新内容と一致させる。

```
NEXT HANDOFF
BASE:              最新 main commit（merge後の実測値）
COMPLETED_THIS_RUN: 今回完了した作業 / PR番号 / merge commit / 確定した結論
FIXED:             今後は固定入力として扱う事実（数値・判定・構造）
UNRESOLVED:        未解決だけ。判断待ち / HOLD / 新発見 を区別して列挙
NEXT:              次の1工程。対象 / Scope / 変更禁止 / 完了条件
DO_NOT_REPEAT:     次のプロンプトで再実行させてはいけない作業
```

このブロックだけで、ChatGPT が次の Claude Code プロンプトを正しく組み立てられる内容にする。

- `BASE` は推測せず、merge 後に実測した commit を書く
- `COMPLETED_THIS_RUN` には裏付け（PR番号 / merge commit）を必ず入れる
- `NEXT` は**1工程だけ**。複数を並べない
- `DO_NOT_REPEAT` には、今回および過去に確定済みで再調査が無駄になるものを具体名で書く
- ChatGPT引き継ぎ用報告（§3）の単一コードブロックの中に含めてよい。
  別ブロックにする場合も、ユーザーが2回コピーするだけで済む形にする

## 3-3. プロンプト生成規則（ChatGPT が次のプロンプトを作るとき）

ユーザーが ChatGPT に「プロンプト」を依頼した場合、次を満たすプロンプトを作る。
Claude Code 側は、受け取ったプロンプトがこの規則に反していたら指摘してから着手する。

- **完了済み作業を実行対象に戻さない。** `DO_NOT_REPEAT` と `COMPLETED` にあるものは対象外
- **固定事項を再調査させない。** `FIXED` / `FIXED_FACTS` は前提として渡す
- **`NEXT` を中心に1工程だけ実行させる。** 「ついでに」を足さない
- **未解決事項を勝手に全部処理させない。** `UNRESOLVED` は参考情報として渡し、
  着手させるものだけを明示する
- **完了報告に次工程判断に必要な情報を残させる。** §3 の9項目と §3-2 のブロックを要求する
- 変更禁止範囲と完了条件を必ず明記する

## 4. 終了条件

作業は、実装や調査が終わっただけでは完了ではない。

実装作業では原則として **検証 → PR作成 → 最終差分確認 → `docs/AI-HANDOFF.md` 更新 → ChatGPT引き継ぎ用報告（NEXT HANDOFF ブロック込み）** までを完了条件とする。
**merge と main 反映確認は Owner（RO-1）の工程であり、Actor の完了条件に含めない**（§2・憲法 §2.6-I1）。

調査のみ、または別の停止点が指示された作業では、指定された停止点を優先する。
その場合も `docs/AI-HANDOFF.md` の `UNRESOLVED` / `NEXT` は実態に合わせて更新する。
