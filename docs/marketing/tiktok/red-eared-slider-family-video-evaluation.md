## 0. 先に断ること（Analytics AI 規範：数字の推測補完は禁止）

**この監査に実測値は 1 件もない。** TikTok Analytics の再生数・プロフィールクリック、
GA4 の `utm_source=tiktok` セッション、いずれも未取得（投稿前のため母数ゼロ）。

本監査が答えるのは、**「流入したときに、それが流入として成立し、計測でき、価値に変わる経路が今あるか」**
という構造の問題だけである。これはリポジトリを読めば実測できる。

## 1. 結論

**動画コンテンツとしては成立している。しかし「流入装置」としては設計されていない。**
**今のまま投稿すると、GA4 の `utm_source=tiktok` セッションは 0 のままになる可能性が高い。**

理由は 1 点に集約される。

> **動画の CTA が、TikTok で唯一クリックできる経路（プロフィールの bio リンク）を指していない。**

動画のラストは「『カメライフガイド』で検索」＋ `kamelifeguide.com` のテキスト表示。
どちらもタップできない。TikTok から外部サイトへ出られる導線は bio リンク（およびアカウント条件を
満たす場合のコメント欄リンク）だけで、動画はそこを一度も案内していない。

これは動画制作時の設計ミスであり、原因は制作側（私）にある。

## 3. 構造上の問題（動画そのもの）

### 3-1. 情報ギャップがゼロ

8 カットで「問い → 答え」が完結している。視聴者は動画だけで
「アカミミガメだ」「逃がすと違法」「飼っていい」「28cm・30年」を得て満足する。
サイトへ行く理由が残っていない。

**保存・シェアには強く、クリックには弱い構造。** これは意図した設計ではあるが、
「流入」を目的に置くなら逆方向に振っている。

### 3-2. CTA の露出が最後の 3.2 秒だけ

24.6 秒のうち CTA が出るのは 21.4〜24.6 秒。
最後まで見なかった視聴者には CTA が一切届かない。

### 3-3. 動線が 3 ステップ

動画を見る → プロフィールをタップ → bio リンクをタップ → サイト。
動画はこの 3 ステップを一度も言語化していない。

## 4. Evidence Protocol

### CLAIM A — 現状の CTA では GA4 `utm_source=tiktok` に流入が計上されない

- **SOURCE**: KPI.md セクション F（「ホームページ流入＝GA4 `utm_source=tiktok` セッション。
  bio リンクの UTM 付与が前提」）= Repository ／ 動画 CTA の実物 = Repository
- **CONFIDENCE**: 高
- **DOUBT**: bio リンクに既に UTM が付いていれば、プロフィール経由の流入は計上される。
  リポジトリからは確認できない（TikTok 側の設定のため）。
- **RECONCILE**: 維持。ただし「bio リンクの現状」を亀好きさんに確認するまで確定としない。

### CLAIM B — `/kid/` の `affiliate_click` は正規スキーマに準拠していない

- **SOURCE**: `js/kid-lookup.js`（`equipment_id`/`channel`/`source`）と
  `js/affiliate-track-static.js`（`provider`/`location`/`category`/`product_id`/`species_slug`/`tier`）の実コード = Repository
- **CONFIDENCE**: 高（パラメータ名の重複ゼロ）
- **DOUBT**: 意図的な別系統として設計・承認済みの可能性がある。経緯を追っていない。
- **RECONCILE**: 保留。事実として報告し、判断は Analytics AI 所管として亀好きさんへ回す。
  （QUALITY.md「計測変更は Analytics AI のレビュー必須」／Project ルール「`affiliate_click` 正規スキーマのみ」）

### CLAIM C — 静止画 4 枚では TikTok のリーチが伸びにくい

- **SOURCE**: なし（**AI Inference**）
- **CONFIDENCE**: 低
- **DOUBT**: 教育系・情報系では静止画＋テロップ形式が機能している例も多い。検証していない。
- **RECONCILE**: **保留。判断材料として使わない。** QUALITY.md により
  AI Inference 単独を確定の根拠にしないため、1 本目の実測が出るまで結論を出さない。

## 5. 選択肢と推奨

### 選択肢 A — 今のまま投稿し、実測を取る

- 利点: MANIFEST「推測で直さない」／ DECISION_RULE「実測値がトリガーを引いたものだけ直す」に忠実。
  1 本目のベースライン（再生数・完視聴率・プロフィールクリック）が取れる
- 欠点: 流入が発生しても計測できない。数字が出ても解釈できない

### 選択肢 B — 流入設計に作り替えてから投稿

- 利点: 最初から流入が測れる
- 欠点: 作り替えの根拠が実測ではなく推測になる。DECISION_RULE の原則に反する

### 推奨 — **A（今のまま投稿）＋ 投稿前の最小 2 点だけ実施**

作り替えは推測なのでやらない。ただし**計測できない状態での投稿は、実測を取る目的そのものを潰す**ため、
計測の穴だけは塞ぐ。これは「直す」ではなく「測れるようにする」なので DECISION_RULE と衝突しない。

**投稿前に必ずやる 2 点（どちらも亀好きさんの操作が必要・所要 5 分）**

1. **TikTok の bio リンクを UTM 付きにする**（KPI.md「取得前の必須設定 ③」）

   ```
   https://kamelifeguide.com/kid/?utm_source=tiktok&utm_medium=social&utm_campaign=hirotta_kame
   ```

   これをやらないと、動画が当たっても KPI 上は 0 に見える。

2. **投稿直後に固定コメントを 1 件置く**

   ```
   容器のサイズ確認はプロフィールのリンクから見られます。
   甲長を選ぶと、今使える容器と卒業した方がいい容器が出ます。
   ```

   動画本編は変更しない。CTA が最後 3.2 秒しかない弱点を、コメント欄で補う。
