# 裁定事項 — Owner の判断を待っているもの

> **Conforms-to: Development Constitution v2.0**
>
> `.claude/rules/pm-conduct.md` §8.7「Owner 判断事項を作業報告に埋めない」に従い、
> 裁定が要る事項をここに分離する。**作業報告の本文には書かない。**
>
> 各項目は次を必ず持つ — 競合している規則（条番号）／選択肢（最低2つ・影響つき）／
> 推奨と理由／**裁定が無い場合に何が止まるか**。
> 裁定が済んだ項目はこのファイルから削除し、確定内容を該当規則へ反映する。

## D-01 — Merge 権限の優先関係（**最優先**）

### 競合している規則

| 出典 | 内容 |
|------|------|
| `DEVELOPMENT_CONSTITUTION.md` §2.6-I1 / §2.3-R1 / §4.3-R1 | Merge は **RO-1（Owner）のみ**が実施 MUST。Actor は Merge しては MUST NOT |
| `.claude/rules/chatgpt-handoff.md` §2 | 実装作業の既定終了点は PR ではなく **merge**。検証PASSなら merge まで進める |
| `.claude/rules/pm-conduct.md` §7 Merge Gate | 検証PASS・BLOCKERなし・危険な変更なしなら **merge 可能** |

憲法 §1.3-R1 では上位（憲法）が優先する。しかし運用実態は下位の2規則に従っている。
**この不整合は今回作ったものではなく、以前から存在していた。**

### 影響（実測）

PR #129・#130 は Merge Gate を根拠に Claude Code が merge した。
**憲法を優先すべきだったなら、この2件は違反である。**

### 選択肢

| 案 | 内容 | 影響 |
|----|------|------|
| **A** | 憲法 §2.6-I1 を改定し、条件付きの Actor merge を認める | 運用実態に合う。憲法改定の手続き（§2.3-R1 憲法改定は RO-2 起案・RO-1 承認）が要る |
| **B** | `chatgpt-handoff.md` §2 と `pm-conduct.md` §7 を憲法に合わせ、Actor は PR 作成で停止する | 憲法を触らない。Owner が全 merge を実施するため Owner の作業が増える |
| **C** | 現状維持（矛盾を残す） | 毎回 Actor がどちらに従うか判断する。**判断が割れ続ける** |

### 推奨

**B**。理由は3つ。

1. 憲法 §1.3-R1 が既に「上位が優先」と定めており、Bは新しい判断を要しない
2. 今日の実績が示すのは「Claude Code の自己判定は当てにならない」ということ。
   無音の動画も低品質な図解も、**Owner が現物を見て初めて止まった**
3. 文書だけの PR なら Owner の merge 負担は小さい。コードやページに触る PR こそ
   Owner が見るべきで、Bはその形になる

ただし **A も合理的**である。Owner の手が塞がると全工程が止まるため、
「文書のみの PR は Actor merge 可」といった限定で A を採る選択もある。

### 裁定が無い場合に止まること

止まらないが、**Actor が毎回どちらかを選ぶ**。選択が割れれば違反が積み上がる。

## D-02 — 品質不足による STOP の扱い

### 競合している規則

| 出典 | 内容 |
|------|------|
| `.claude/rules/closeout-gate.md` | `CLOSE NOW` は同じ作業内で完了まで進める／`BLOCKED` を理由に他を止めない／1件ずつ承認待ちにせず一括処理する |
| `.claude/rules/pm-conduct.md` §8.4（新規・実務原則） | 品質不足による STOP は失敗として扱わない |

`closeout-gate.md` は**「面倒だから後回し」と「品質が基準に達していないから止まる」を区別していない**。
厳密に読むと後者まで抑止される。

### 影響（実測・2026-09-03）

図解オーバーレイの品質不足で作業を止めたのは、本件で最も価値のある判断だった。
だが `closeout-gate.md` を厳密に適用すれば、止めずに完成させるべきだった。

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | `closeout-gate.md` に一文追加 —「成果物が品質基準に達していないと判断した場合の STOP は、積み残しではなく CLOSE の一形態として扱う」 |
| **B** | 追加しない。`pm-conduct.md` §8.4 だけで運用する |

### 推奨

**A**。§8.4 は PM 向けの実務原則であり、`closeout-gate.md` は**全継続作業**に適用される。
止める側（実装）が読む規則に書かなければ効かない。追加は1文で、既存の意味を変えない。

### 裁定が無い場合に止まること

止まらないが、**実装側が品質不足でも走り切る圧が残る**。

## D-03 — 「合格基準を下げない」と「検査を追加する」の区別

### 対象の規則

`.claude/rules/pm-conduct.md` §4 —「成功条件は作業開始前に固定し、**結果を見て合格基準を下げない**」

この規則は維持すべきである。ただし文言は「結果を見て変えるな」とも読める。

### 影響（実測・2026-09-03）

本件では失敗を発見してから検査を4つ追加した（G9 ナレーション重なり／
G10 帰属表示／G11 未宣言カット／G12 図解の実在）。**いずれも基準を上げている。**
厳密に読むと、この改善ループが禁止される。

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | §4 に一文追加 —「合格基準の**引き下げ**を禁止する。実害を発見して**検査を追加する**ことは、この禁止に当たらない」 |
| **B** | 追加しない（現行文言のまま運用） |

### 推奨

**A**。追加は1文で、禁止の範囲を明確化するだけであり緩和ではない。

### 裁定が無い場合に止まること

止まらないが、**検査を増やす改善が「基準の後付け変更」と解釈されうる**。

## D-04 — Short Video Gate のデッドロック

### 対象の規則

`.claude/rules/pm-conduct.md` §6 — 自前撮影なしの場合、正式APIキーまたはローカル配置で
取得した**商用利用可能で権利確認可能な HD 以上のカメ生体実写映像**が無ければ、
動画レンダリングを完成扱いにしない。

### 影響（実測）

素材監査（`experiments/kame-video-audit/AUDIT.md`・別リポジトリ）の結論:

- 台帳1,000スロット（Pexels / Pixabay）は **BLOCKED_API_KEY**。
  実測 — Pexels `HTTP 401 Missing API key` / Pixabay `HTTP 400 Invalid or missing API key`
- 実体297件を個別監査、95件を取得・全尺確認
- Mixkit のカメ動画22本は **全て Restricted License（personal use only）** で収益化不可
- **日本の飼育主要種**（クサガメ・ニホンイシガメ・ニオイガメ・チズガメ・ハコガメ類）で
  見どころがあり商用利用可の実写は**ほぼ存在しなかった**
- 商用可で強かったのはリクガメ（ケヅメ／サバクゴファー）とスライダー類に偏る

**自前撮影をしない方針**と合わせると、現状の素材調達のままでは
**動画は永久に完成扱いにできない。**

### 選択肢

| 案 | 内容 | 影響 |
|----|------|------|
| **A** | Pexels / Pixabay の無料APIキーを取得し repo secret へ登録 | 1,000スロットが開く。取得は Owner のアカウント作成が必要 |
| **B** | CC BY-SA 4.0 の継承条件を受け入れる | 監査TOP1（ケヅメが草を食べる超接写 1920×1012）とTOP3（幼体スライダーが水槽を泳ぐ 1920×1080）が使える。**完成動画も BY-SA で公開する義務**が生じる |
| **C** | 動画制作を一旦停止する | サイト本体の改善に集中する |
| **D** | §6 を緩める | **推奨しない**。緩めれば低品質な成果物が「完成」になる |

### 推奨

**A と B の併用**。A は素材の母数を増やし、B は**日本の飼育者に刺さる素材**を今すぐ使える。
D は採らない。§6 は今回 Owner が確定した規範であり、実現できないから緩めるのは
`pm-conduct.md` §4「結果を見て合格基準を下げない」に反する。

### 裁定が無い場合に止まること

**動画制作が止まる。** 現在の素材では §6 を満たせないため、
何を作っても「完成扱いにしない」で終わる。

## D-05 — PM 実務原則（§8）の承認

`.claude/rules/pm-conduct.md` §8 は **Claude Code 起案**（Owner の指示による）であり、
§1〜§7（Owner 確定）とは出所が異なる。§8 冒頭にその旨を明記済み。

7原則 — 8.1 Artifact First／8.2 反証可能な受入基準／8.3 PM 自身の数値にも出所／
8.4 STOP を成果として扱う／8.5 一度に1工程／8.6 自著の唯一の判定者にならない／
8.7 Owner 判断事項を作業報告に埋めない

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | 全7原則を承認し、§1〜§7 と同格の規範に格上げする |
| **B** | 実務原則のまま維持する（上位規範と競合すれば §1〜§7 と憲法が優先） |
| **C** | 一部を削除・修正する |

### 推奨

**B**。§8 は本件1セッションの観察にもとづく。**格上げは複数案件で有効性を確認してからでよい。**
ただし **8.1（Artifact First）だけは A** を推す。今日の重大欠陥3件すべてを検出した唯一の手段であり、
根拠が実測である。

### 裁定が無い場合に止まること

止まらない。§8 は実務原則として機能する。
