## D-01 — Short Video Gate のデッドロック

### 対象の規則

`.claude/rules/pm-conduct.md` §6 — 自前撮影なしの場合、正式APIキーまたはローカル配置で
取得した**商用利用可能で権利確認可能な HD 以上のカメ生体実写映像**が無ければ、
動画レンダリングを完成扱いにしない。

### 2026-09-03 追加実測 — 前提が変わった（素材源サーベイ）

`ai-tiktok-company` の `experiments/kame-source-survey/SOURCES.md`（実測・runner 上で取得）:

- Wikimedia Commons のカメ動画を**ソース単位で数え直した**（鍵不要の公式 API・per-item ライセンス取得）
  → **176件**（video mime・ウミガメ/AI除外）。**全件が商用利用可。HD以上152件。最大 3840×2160。実DL成功**
- ライセンス内訳: Public domain 74 / CC0 5 / CC BY 系 50 / CC BY-SA 系 47
  → **継承義務が無いものが129件ある**
- HD上位を実際にダウンロードして**全部目視した**結果の歩留まり:
  **PD/CC0 = 3/14（21%）**、**CC BY（継承なし）= 9/12（75%）**
- **水槽の中で餌を食べる個体の水中接写（1920×1080 / CC BY 3.0）が存在した。**
  第2弾で「Restricted License でしか手に入らない」と結論していた"飼育シーンそのもの"である

**したがって「§6 を満たす素材が存在しない」という D-01 の前提は成立しない。**
動画制作を始めるために CC BY-SA の継承条件を受け入れる必要は無い。

なお「176件」は使える本数ではない。目視した14件中7件はカメが1匹も写っておらず、
キーワード一致は実物を保証しない。**目視ゲートを工程に入れることが前提条件になる。**

### 影響（第2弾時点の実測・上記により一部が過去のものになった）

素材監査（`experiments/kame-video-audit/AUDIT.md`・別リポジトリ）の結論:

- 台帳1,000スロット（Pexels / Pixabay）は **BLOCKED_API_KEY**。
  実測 — Pexels `HTTP 401 Missing API key` / Pixabay `HTTP 400 Invalid or missing API key`
- 実体297件を個別監査、95件を取得・全尺確認
- Mixkit のカメ動画22本は **全て Restricted License（personal use only）** で収益化不可
- **日本の飼育主要種**（クサガメ・ニホンイシガメ・ニオイガメ・チズガメ・ハコガメ類）で
  見どころがあり商用利用可の実写は**ほぼ存在しなかった**
- 商用可で強かったのはリクガメ（ケヅメ／サバクゴファー）とスライダー類に偏る

**自前撮影をしない方針**と合わせると、現状の素材調達のままでは
**動画は永久に完成扱いにできない。**

### 選択肢

| 案 | 内容 | 影響 |
|----|------|------|
| **E（新）** | **Wikimedia Commons の CC BY（継承なし）を主レーンに固定して制作を再開する** | 鍵不要・$0・per-item ライセンスが機械取得可・1080p。**BY-SA の継承義務を負わない**。帰属表記は作者名がAPIで取れるため SHORTS GATE の G10 で機械検査できる |
| **A** | Pexels / Pixabay / Flickr の無料APIキーを取得し repo secret へ登録 | 母数が増える。**固定先を変える必要はない**（Commons を主・鍵付きストックを副）。Owner のアカウント作成が必要 |
| **B** | CC BY-SA 4.0 の継承条件を受け入れる | 第2弾TOP1（ケヅメが草を食べる超接写）とTOP3（幼体スライダー）が使えるが、**完成動画も BY-SA で公開する義務**が生じる。**上記実測により、制作開始の必須条件ではなくなった** |
| **C** | 動画制作を一旦停止する | サイト本体の改善に集中する |
| **D** | §6 を緩める | **推奨しない**。緩めれば低品質な成果物が「完成」になる |

### 推奨

**E 単独で再開できる。** A は任意（母数を増やすだけで、固定先の変更を伴わない）。
**B は保留してよい** — 継承義務を負わずに始められることが実測で分かったため、
BY-SA は「どうしてもその1本が要るとき」に個別判断すればよい。D は採らない。
§6 は Owner が確定した規範であり、実現できないから緩めるのは
`pm-conduct.md` §4「結果を見て合格基準を下げない」に反する。

**E を採る場合の必須条件（実測にもとづく）**: 目視ゲートを工程に入れること。
機械一致だけで採用すると、カメが写っていない素材が約半数混入する。

### 裁定が無い場合に止まること

**動画制作が止まったままになる。** ただし止まる理由はもう「素材が無いから」ではなく、
**どのレーンで再開するかが決まっていないから**である。

## D-04 — SHORTS GATE の G4 / G6 がカメ動画の実測と矛盾する

### 対象の規則

`ai-tiktok-company` の `experiments/shorts-gate/criteria.json`（BLOCK ゲート）

| ゲート | 内容 | 出所 |
|---|---|---|
| **G4** `opening_caption_held` | 冒頭テロップを **3.0秒以上**保持することを必須 | 科学・教育系ショート13本の実測（`real-video-study/STUDY.md`） |
| **G6** `spoken_question_declared` | **音声で問い**を提示することを必須 | 同上（上位6/6・下位0/6 の最強判別子だった） |

### 影響（2026-09-04 実測）

カメ動画19本（上位10・下位9／YouTube Data API の再生数実測＋Gemini のネイティブ動画解析）で、
**この2つはカメ動画では成立しなかった。**

| 項目 | 上位10本 | 下位9本 | 判定 |
|---|---|---|---|
| テロップあり | 4/10 | **9/9** | **テロップは下位群の特徴**。冒頭テロップ必須は上位の型に反する |
| 音声で問いを提示 | 6/10 | 7/9 | **判別しない**（科学系では6/6 vs 0/6 だった） |

代わりに判別したのは **0秒で顔と目が見えていること**（10/10 vs 4/9・顔100% vs 57.5%）、
**尺13.5秒**（vs 58秒）、**カット0**（vs 20）、**payoff 3.5秒**（vs 53秒）、
**BGMなし＋原音**（vs 音楽＋ナレーション）。

**このまま作ると、実測で最も強い構成が現行ゲートで BLOCK される。**

### 選択肢

| 案 | 内容 | 影響 |
|----|------|------|
| **A** | **ジャンル別プロファイルを作る**（`science` と `kame` を分ける）。`kame` では G4・G6 を外し、代わりに実測した判別子を新ゲートにする（0秒被写体・顔/目の可視率・尺上限・payoff秒） | 実測に忠実。両ジャンルの知見が両方残る。criteria.json の構造変更が要る |
| **B** | G4・G6 を全ジャンルで撤廃する | 科学系13本の実測を捨てることになる。**推奨しない** |
| **C** | 現行ゲートを維持し、カメ動画も冒頭テロップと音声の問いを入れる | 実測で下位群の型を強制することになる。**推奨しない** |
| **D** | 判断を保留し、動画制作を止める | 進まない |

### 推奨

**A**。G4・G6 は科学・教育系では実測された正しい判別子であり、撤廃する理由はない。
問題は**カメ動画で検証されていないものを流用していたこと**。
ジャンルを分けて、それぞれ実測にもとづくゲートを持たせる。

**これは合格基準の引き下げではない。** 実害（実測で最強の構成が BLOCK される）を発見して
検査を作り直すことであり、`pm-conduct.md` §4 の但し書き（2026-09-03 裁定 D-03・案A）に該当する。

### 裁定が無い場合に止まること

**次の1本が作れない。** PLAYBOOK の⑦（15秒・ノーカット・原音のみ・テロップ0枚）は
現行ゲートの G4 で必ず BLOCK される。

## D-02 — PM 実務原則（§8）の承認

`.claude/rules/pm-conduct.md` §8 は **Claude Code 起案**（Owner の指示による）であり、
§1〜§7（Owner 確定）とは出所が異なる。§8 冒頭にその旨を明記済み。

7原則 — 8.1 Artifact First／8.2 反証可能な受入基準／8.3 PM 自身の数値にも出所／
8.4 STOP を成果として扱う／8.5 一度に1工程／8.6 自著の唯一の判定者にならない／
8.7 Owner 判断事項を作業報告に埋めない

### 選択肢

| 案 | 内容 |
|----|------|
| **A** | 全7原則を承認し、§1〜§7 と同格の規範に格上げする |
| **B** | 実務原則のまま維持する（上位規範と競合すれば §1〜§7 と憲法が優先） |
| **C** | 一部を削除・修正する |

### 推奨

**B**。§8 は本件1セッションの観察にもとづく。**格上げは複数案件で有効性を確認してからでよい。**
ただし **8.1（Artifact First）だけは A** を推す。今日の重大欠陥3件すべてを検出した唯一の手段であり、
根拠が実測である。

### 裁定が無い場合に止まること

止まらない。§8 は実務原則として機能する。
