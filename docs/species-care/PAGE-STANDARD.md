# speciesページ標準（C3確立・2026-08-17）

基準ページ: `species/musk-turtle.html`（ミシシッピニオイガメ）
目的: 「海外情報の翻訳」ではなく、公的・学術資料で検証した事実を
日本の気候・住宅・水槽規格・法規制・国内商品に合わせて再構成したページの完成形。

## 1. データの流れ（必須）

```
species-master.json（正本）
  └ care項目（verification / provenance / sources / japan_fit）
      └ ページへ反映するのは CONFIRMED / LIKELY のみ
        UNPROVEN は断定表現でページに書かない
```

- ページ独自の数値を新規に作らない。master に無い数値を書きたくなったら
  先に master へ根拠つきで登録する。
- 既存ページの良い部分（構成・FAQ・診断導線）は壊さない。追記主体。

## 2. 必須セクション（追加分）

1. **「日本の住まい・季節に合わせた飼い方」**
   - 大きさの上限（実測記録・出典つき）
   - 水槽ステップ（日本の30/45/60/90/120cm規格で表現。海外のガロン・
     インチは必ず換算し、原文の単位は出さない）
   - 種の運動特性に基づくレイアウト指針（例: 底歩き種→浅さ＋足がかり）
   - 夏（高温多湿）・冬（低温）の日本の季節対応
2. **「出典・参考資料」**
   - 公的機関・学術・専門団体のみ。ショップ記事は載せない
   - 末尾に「断定していない項目がある」ことを明記（不明は不明）

## 3. 整合性チェック（公開前に必ず）

- 法規制stat が master の CITES/国内規制と一致しているか
  （C3で「制限なし」→「CITES II」の誤りを実際に検出・修正した）
- ページ内で同じ項目の数値が食い違っていないか
  （C3で寿命 20〜30年 vs 20〜50年 の不整合を統一した）
- `python3 tools/validate_species.py --strict` が通ること
- JSON-LD が全ブロックパースできること

## 4. 商品の載せ方

- 順序は必ず「飼育条件 → 必要性能 → 国内商品」
- 商品は既存の検証済み経路のみ:
  - mountStarterKit（equipment.js の実在確認済みASIN）
  - data/products.js（楽天API自動更新）
- 性能を確認できない商品は載せない。該当カテゴリの適合商品が無ければ
  そのカテゴリは空欄にする（例: リクガメのZone3 UVBは照度表確認まで保留）
- 価格を本文に固定値で書かない（変動情報は楽天API側でのみ扱う）

## 5. SEO運用

- title / URL は実験期間中変更しない（追記のみで検証する）
- 対象ページの主要クエリを kame-growth 週次scanの定点観測に登録し、
  baseline（90日実測）を data/analysis/ に保存してから公開する
- 判定は4週後。効果が確認できたら次の種へ横展開する

## 6. 禁止事項

- 個人情報・実飼育写真の使用
- UNPROVEN項目の断定・数値の創作・海外値の単位ごと直写し
- 収益目的での飼育条件の変更
