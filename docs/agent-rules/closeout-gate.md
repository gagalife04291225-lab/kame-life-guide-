# CLOSEOUT GATE — 未完了を積み上げない恒久ルール

このルールは KAME LIFE GUIDE の全継続作業に適用する。
**Claude Code / OpenAI Codex / GPT-6 Astra など、どのエージェントで作業する場合も同じ。**

## 基本原則

工程を細切れにして「後で」「次回」に回し、未完了項目を積み上げてはならない。
同一テーマ・同一工程で、現在の情報と権限で完了可能な関連作業は、原則として同じフェーズ内で最後まで実施して CLOSE する。

## 開始時ゲート

作業開始時に `docs/AI-HANDOFF.md` と直近報告を読み、既存残件を次の4分類へ整理する。

- `CLOSE NOW` — 今すぐ完了可能。同じ工程で実装・検証まで行い CLOSE する。
- `BLOCKED` — 外部データ、権限、素材などが不足。何が揃えば再開できるかを具体的に固定する。
- `DECISION` — ユーザー判断が必要。選択肢・根拠・影響を固定し、判断以外の再調査を繰り返さない。
- `DROP` — 効果が無い、不要、または完了済み。次工程へ持ち越さない。

`後でやる`、`次回確認`、`必要なら対応` のような再開条件の無い曖昧な残件は禁止。

**品質不足による STOP は積み残しではない**（2026-09-03 Owner 裁定 D-02・案A）。
成果物が品質基準に達していないと判断して止めた場合、それは `CLOSE` の一形態として扱い、
未完了項目の積み上げとして扱わない。本ゲートが禁じているのは
「面倒だから後回しにする」ことであり、「基準に達していないから出さない」ことではない。

## 実行ルール

1. `CLOSE NOW` に分類した同一テーマの関連項目は、途中で別フェーズへ逃がさず、同じ作業内で実装→検証→完了まで進める。
2. 1項目を直した結果、同じ原因・同じ工程に属する未完了が判明した場合、それも原則として同工程で閉じる。
3. `BLOCKED` を理由に、ブロックされていない同一工程の作業まで停止しない。
4. `BLOCKED` は必要入力・取得方法・再開条件を明記して隔離する。
5. `DECISION` はユーザーが判断できる状態まで情報を揃える。判断待ちを理由に無関係な作業を止めない。
6. 完了済み・確定済みの監査や調査は再実行しない。再検証は NO-REWORK GATE の4条件に該当する場合だけ。
7. 新しい監査で残件を増やすこと自体を成果としない。発見した問題は上記4分類へ必ず着地させる。

## 終了ゲート

作業終了時は、そのテーマについて以下を満たすまで `完了` としない。

- 今すぐ処理可能な項目が残っていない。
- BLOCKED は再開条件が具体化されている。
- DECISION は選択肢と判断材料が揃っている。
- DROP は理由が記録されている。
- 完了済み項目は `COMPLETED` / `FIXED_FACTS` に移され、再作業対象から外れている。

`NEXT` を設定する場合も、単なる「後でやる」ではなく、現在のテーマをCLOSEした後の独立した次工程だけを置く。

## push 後のデプロイ検証（全エージェント共通）

`git push` の後は、GitHub Pages のデプロイ完了を待って（目安60秒）、
変更したページを実際に取得し、内容が反映されているか検証してから完了とする。

確認先: https://kamelifeguide.com および今回変更したページのURL

> Claude Code では `.claude/settings.json` の PostToolUse hook がこの確認を自動で促すが、
> **この検証は Claude 固有の手順ではない。** 他のエージェントで作業する場合は hook が
> 動かないため、本節を根拠に手動で実施する。ドキュメントのみの変更で
> 配信内容に差分が出ない場合は、その旨を報告に明記して省略してよい。

## 引き継ぎ報告

外部AI/実装エージェントの最終報告では、残件を必ず `CLOSED / BLOCKED / DECISION / DROP` に分類する。
BLOCKED には再開条件を付ける。
報告はスマホで1回コピーできるよう「ChatGPT引き継ぎ用報告」を含む単一コードブロック1個で出力する
（タイトル文字列は既存運用との互換のため変更しない）。
