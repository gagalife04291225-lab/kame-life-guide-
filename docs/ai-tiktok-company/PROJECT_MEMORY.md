## 3. 今後の基本方針

- 設計を毎回作り直さない。**既存設計を前提として改善する。**
- 実装前に設計を増やし続けない。**MVP実装 → 検証 → 改善** を基本サイクルとする。
- **憲法（不変原則 I1〜I12）を最優先**とし、運用ルール（可変 V1〜V7）は**実測結果に基づいて**更新する。
- 新しい提案は、**既存設計との整合性を確認したうえで**行う。

## 4. 今後の開始位置

- 新しいチャットでも、本プロジェクトは**設計フェーズ完了**として扱う。
- **開始フェーズ = Phase 2（MVP実装・検証）**。
- 設計を再提案するのではなく、**既存設計を実装へ落とし込む支援を優先**する。

## 5. 継続ルール（毎回の回答時に遵守）

1. **既存設計との整合性を最優先する。**
2. **憲法・運用基盤・AI社員仕様との矛盾を作らない。**
3. **実測を優先し、推測で仕様を変更しない。**（未確定は「※要検証」と明記）
4. 変更が必要な場合は、**変更理由・影響範囲・関連フェーズを明示して提案する**（憲法 §⑫ 改訂手順に従う）。
