## 0. 最初に — 依頼された測定のうち、実行できなかったもの

依頼は「TikTok動画100本（成功）＋100本（失敗）を実測し、35項目を数値化する」だった。
**この環境からは TikTok・YouTube のいずれにも到達できないため、他者動画の実測は実行できていない。**

  {"kind":"connect_rejected",

   "host":"www.tiktok.com:443"}

yt-dlp 等のダウンローダも未導入で、導入しても上記ポリシーにより取得できない。

### 代わりに実行したこと

| # | 実行内容 | 位置づけ |
|---|----------|----------|
| 1 | 公開されている**大規模実測研究**を収集（n=18,000,000投稿 / n=34,635本 / n=11,400,000投稿 など）。自前の100本より桁違いに大きい標本 | 二次実測（出典明記） |
| 2 | **フレーム解析器を自作**（`analyze_video.py`）。カット長・画面変化・静止時間・ズーム傾向・色・輝度・冒頭挙動を1本あたり全フレーム走査で算出 | 一次測定の道具 |
| 3 | 解析器を**自作動画3本に適用して検証**。実際に欠陥（静止2.6秒・カット0本）を検出できることを確認 | 道具の妥当性検証 |
| 4 | 測定不能項目を**空欄のまま残す**（数値を作らない） | 品質基準 |

**この解析器はオーナーのローカル環境（TikTokに到達できる環境）で実行すれば、
依頼どおり100本の一次実測がそのまま可能になる。** 研究の再現手順は §6 に記す。

## 2. Phase 3 成功の構造化（偶然を除外する）

偶然（1本だけの当たり・トレンド音源の一過性・時事ネタ）は除外し、
**複数の独立した大規模標本で再現している事実だけ**を残した。

```
成功の構造（因果の順序）

 [1] 冒頭1.5秒で「自分ごと」と判断させる
       ↓  ← A1/A2: 配信判断も視聴判断もこの時点で終わる
 [2] 3秒保持率が70%を超える
       ↓  ← A3/A5: ここが全体の90%を決める
 [3] 1.5〜2.0秒ごとに画面が変わり、再判断のたびに残る
       ↓  ← D1/D2/D3/D4
 [4] 完走する（70%基準）
       ↓  ← A9/F5: 尺ではなく完走が効く
 [5] 保存・シェアされる（＝後で見返す価値がある）
       ↓  ← C1/C2
 [6] ループ・再視聴が起きる
       ↓  ← C3
 [7] 配信が拡大する
```

**教育コンテンツがこの構造に強い理由**（B2: 7.36%）:
[5]の「後で見返す価値」を構造的に持っているから。娯楽系は[5]で落ちる。

## 6. 再現手順（オーナーのローカル環境で100本を一次実測する）

```bash
# 1) 取得（TikTokに到達できる環境で）
pip install yt-dlp numpy imageio-ffmpeg
yt-dlp -o "success/%(id)s.mp4" <URL1> <URL2> ...   # 100万再生以上の成功動画
yt-dlp -o "fail/%(id)s.mp4"    <URL1> <URL2> ...   # 伸びなかった動画

# 2) 一次実測（全フレーム走査）
python3 tiktok/research/analyze_video.py success/*.mp4 --out research/success
python3 tiktok/research/analyze_video.py fail/*.mp4    --out research/fail

# 3) 出力
#    measurements.json … 1本ごとの全指標
#    measurements.md   … 比較表（平均/中央値/分散つき）
```

取得した measurements.json を突き合わせれば、Phase 2 が求めた
**平均・中央値・分散**を成功群/失敗群で比較できる。
本レポートはその一次実測が入った時点で v2 に更新する。
