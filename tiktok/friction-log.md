# TikTok制作 friction-log

> ただし「次の動画が作れないブロッカー」は即修正する。

## #1「カメって甲羅を脱ぐと思ってない？」（2026-07-31）

| # | 内容 | 種別 |
|---|------|------|
| 1 | GPU・画像生成モデルなし → 実写風AI画像を生成できない。図解＋実写差し替え方式で回避 | 制約 |
| 2 | TTS（日本語音声）なし → ナレーションは手動録音が必要。工程が分断される | 制約 |
| 3 | ブランドフォント(Noto Sans JP)を取得できず IPAGothic で代用。公開版では要差し替え | 改善 |
| 4 | TikTokのセーフエリア実値が未確定。保守的値(右22%/下28%)で運用中。要実機確認 | 要検証 |
| 5 | 目視QCを2周実施。テロップ幅とセーフエリアは**自動検証化できた**（2本目以降は自動で弾ける） | 改善済 |
| 6 | 図解のプログラム描画が有効。2本目以降も同方式なら素材調達コストがゼロ | 知見 |

## #1 v2「モーショングラフィックス版」（2026-07-31）

| # | 内容 | 種別 |
|---|------|------|
| 7 | 静止カード方式（v1）は「スライドショー禁止」要件を満たさない。全フレーム毎に再描画するモーション方式へ全面書き換え | 改善済 |
| 8 | 骨の数を「60個」と断定表示していたが出典の確度は中。「およそ50〜60個」に修正 | 事実精度 |
| 9 | カウントアップ演出は途中の数値（例「36個」）がスクショで事実として切り取られる。**演出より正確性**を優先し全削除 | 事実精度 |
| 10 | 暗転トランジションが強すぎて空フレームが発生（blend 0.5→0.20 / 0.12s→0.07s） | 改善済 |
| 11 | 光沢スイープが強いと安っぽい（alpha 0.10→0.055）。ブランドの高級感は「動かしすぎない」ことで保たれる | 知見 |
| 12 | 全フレーム描画は 870フレームで約3分。尺30秒までは許容。60秒動画を作るなら要最適化 | 要検証 |

## #1 v3「Design System v1.0 準拠版」（2026-07-31）

| # | 内容 | 種別 |
|---|------|------|
| 13 | **TikTok/YouTube へネットワーク到達不可**（gateway 403）。他者動画100本の一次実測はこの環境では不可能。測定器を作ってオーナー環境で実行する形に切り替えた | 制約 |
| 14 | フレーム解析器を自作したところ、v1が「カット0本・最長静止39.97秒」と判明。**目視で気付けなかった欠陥を数値が先に見つけた** | 知見 |
| 15 | 警告色 `#c85a4a` がコントラスト 4.09:1 で AA 不合格 → `#e0705c`(5.41:1)。制作前チェックが自動で止めた | 改善済 |
| 16 | 縦方向のセーフエリア検証が v2 まで無く、v3 で入れたら6箇所違反していた | 改善済 |
| 17 | 「最長静止」はフレーム全体の平均差分で測るため、**細い線の動きは検出されない**。大面積（背景光）を動かす必要がある | 知見 |
| 18 | ライトスイープを動き確保のため強くしたら安っぽくなった（目視QC）。alpha 0.075→0.026 に戻し、動きは背景の呼吸で確保 | 改善済 |
| 19 | フックで骨を先に見せてしまい、後半のリビールを潰していた。順序を「カメ→寄り→否定」に修正 | 改善済 |
| 20 | コメント誘導とループ接続が抜けていた（分析項目にあったのに設計に落ちていなかった）。分析項目→DS→制作のトレースを表で持つべき | 改善 |
| 21 | 音声を生成しても**試聴して検品する手段がない**。検品できない成果物は出さない方針で無音のまま納品 | 制約 |
